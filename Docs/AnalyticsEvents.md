# Аналитика MergeTD

## Включение отправки

Модуль PluginYG2 Metrica установлен. Пока `Metrica Counter ID = 0`, отправка в релизном WebGL отключена. В Unity Editor события доступны в Console как `Metrica send` при включённых `Metrica / Log` и `Basic / Log In Editor`.

1. Создайте счётчик на https://metrika.yandex.ru/ для своей игры. Снимите ограничение «Принимать данные только с указанных адресов».
2. Откройте настройки Plugin Your Games, раздел Metrica. Оставьте модуль включённым и укажите числовой `Metrica Counter ID`. Если настройка ID переопределяется настройками платформы YandexGames, укажите тот же ID там.
3. Создайте отдельную цель типа «Целевое событие» для каждого нужного имени из списка ниже. Используйте точное совпадение.
4. Соберите WebGL, загрузите в черновик Яндекс Игр. Откройте игру с `_ym_debug=1` и проверьте `Reach goal` в контексте игрового iframe DevTools. Для новой опубликованной сборки требуется обычная модерация.
5. Смотрите конверсии, параметры событий и воронки. Денежный доход сверяйте с Консолью Яндекс Игр: события не передают цену или рекламную выручку.

## Общие параметры и частота

Каждое событие содержит `build_version`. Во время забега добавляются `run_id` и `wave`. Длительность измеряется реальным временем, включая паузы и рекламу. `session_attempt` — номер запуска забега в текущем сеансе приложения.

События, помеченные как агрегаты, группируются по параметрам. Отправка происходит каждые 30 секунд, на границах волн, при переходе в меню и потере фокуса. В агрегате `count` — число действий, `amount` — сумма указанной величины. Достижения цели для агрегатов показывают число отправленных групп, а не число отдельных действий.

Повторные отправки одной цели разделены минимум 1,05 секунды. В очереди хранится до 256 событий, включая ожидание SDK. Порядок событий сохраняется: ограничение частоты может задерживать доставку следующих событий. Отправка при закрытии вкладки и доставка при блокировке Метрики не гарантируются. В Метрике действует лимит 400 достижений онлайн-целей за визит; для длинных сеансов следует учитывать этот предел при выборе целей.

## События

| Имя цели | Момент и параметры |
| --- | --- |
| `game_ready` | Главное меню впервые завершило активацию; `loading_seconds`. |
| `run_start` | Подготовлен новый забег; `session_attempt`. |
| `wave_start` | Начата волна; `is_boss`. |
| `wave_complete` | Волна завершена; `duration_seconds`, `base_health`, `base_max_health`. |
| `wave_defeat` | База уничтожена во время волны; `duration_seconds`, `army` (типы и уровни башен). |
| `run_complete` | Завершена последняя волна; `duration_seconds`, `revive_count`. |
| `run_exit` | Забег завершён без победы; `reason`, `duration_seconds`, `revive_count`. Закрытие вкладки сюда не входит. |
| `revive_used` | Возрождение успешно применено; `method`, `revive_count`. |
| `run_unlocked` | Первое выполнение условия открытия следующего забега; `unlocked_run_id`. Загрузка существующего прогресса не считается открытием. |
| `tower_buy` | Агрегат успешных покупок в меню и бою; `tower_type`, `level`, `currency`; `amount` — суммарная стоимость. |
| `tower_merge` | Агрегат успешных слияний в меню и бою; `tower_type`, полученный `level`; `count` — число слияний. |
| `tower_upgrade` | Агрегат улучшений башен; `upgrade_id`, `level`, `upgrade_type`; `amount` — золото. |
| `base_upgrade` | Агрегат улучшений базы и её ресурсов; `upgrade_id`, `level`, `upgrade_type`; `amount` — золото. |
| `tower_slot_unlocked` | Куплено место армии; `slot_id`, `price`. |
| `card_selected` | Выбрана допустимая карта; `card_id`, список `choices`. |
| `spell_unlocked` | Заклинание фактически открыто; `spell_id`, `source`. |
| `spell_upgrade` | Куплен уровень заклинания; `spell_id`, `level`, `price` в кристаллах. |
| `spell_used` | Агрегат реальных применений всех семи заклинаний; `spell_id`; `amount` — суммарная стоимость маны. Выбор цели без применения не считается. |
| `generator_used` | Агрегат циклов производства генераторов; `amount` — фактически добавленная мана, `count` — число циклов, включая циклы при полном запасе. |
| `currency_earned` | Агрегат начислений золота/кристаллов; `currency`, `source`; `amount` — фактическое начисление с учётом предела. |
| `currency_spent` | Агрегат списаний золота/кристаллов; `currency`, `source`; `amount` — расход. |
| `resource_shortage` | Агрегат неудачных покупок башни в бою; `action`, `currency`, `available`; `amount` — суммарная требуемая стоимость. |
| `quest_complete` | Задание достигло цели; `quest_id`, `category`. Восстановление задания из сохранения не считается выполнением. |
| `reward_claimed` | Выданы ежедневная награда или награда задания; `source`, `day_index`/`quest_id`, `gold`, `gems`. Для волн — агрегат выдач с `source=wave`. |
| `energy_empty` | Агрегат попыток запуска без энергии. |
| `energy_refilled` | Восстановлена энергия запуска; `method=shop_offer` с `amount`, либо агрегат `method=time` с суммой `amount`. |
| `shop_open` | Панель магазина действительно видна; `source` — имя корневого UI элемента. |
| `offer_view` | Карточка пересекла видимую область; `offer_id`, `placement`. Один раз на открытие панели, независимо от обновления таймера. |
| `purchase_start` | Начата покупка за реальные деньги; `product_id`, `offer_id`. |
| `purchase_success` | SDK сообщил успех ожидаемой новой покупки; `product_id`, `offer_id`. Восстановление старых покупок не отправляет эту цель. |
| `purchase_error` | Ожидаемая оплата не завершена; `product_id`, `offer_id`, `reason=cancelled_or_error`. Текущий PluginYG2 не различает эти причины. |
| `purchase_delivered` | Набор фактически выдан за любую поддерживаемую оплату; `offer_id`, `product_id`, `payment_type`, `is_restore`, `gold`, `gems`, `energy`, `spell_id`. |
| `rewarded_request` | Запрошена реклама за награду; `placement`. |
| `rewarded_open` | SDK сообщил открытие; `placement`. |
| `rewarded_earned` | SDK подтвердил засчитанный просмотр; `placement`. Факт сохранения награды проверяется отдельным игровым событием. |
| `rewarded_close` | SDK сообщил закрытие; `placement`. Закрытие не означает награду. |
| `rewarded_error` | SDK сообщил ошибку; `placement`. |
| `interstitial_request` | Игра вызвала межстраничную рекламу; `placement`. SDK может пропустить запрос по своему таймеру. |
| `interstitial_open` | SDK сообщил открытие; `placement`. |
| `interstitial_close` | SDK сообщил закрытие; `placement`, `was_shown`. |
| `interstitial_error` | SDK сообщил ошибку; `placement`. |
| `save_error` | Агрегат исключений чтения JSON мира/чекпоинта и записи локального мира; `storage`, `stage`, при записи `error_type`. |
| `save_recovered` | Мир загружен из локальной резервной копии; `source=local_backup`. |
| `loading_error` | Агрегат ошибок Unity до готовности меню, после запуска наблюдателя; `error_code`, `error_type`. |
| `game_error` | Агрегат ошибок Unity после готовности; `error_code`, `error_type`. |

`error_code` — хеш сообщения, а не его текст. За сеанс учитывается до десяти разных сообщений. Сообщения об успешной аналитике не вызывают повторных ошибок аналитики.

## Границы покрытия

В проекте не найдена система обучения: события `tutorial_*` не отправляются. Загрузка WebGL до запуска Unity и асинхронные ошибки облачной записи, которые PluginYG2 оставляет только в JavaScript, не покрыты наблюдателем C#.

Источники общего начисления без отдельного обработчика имеют `source=gameplay`. Отдельно выделены покупки башен, продажа в меню, карты, награды волн и заданий, ежедневные награды, магазин и улучшения.

## Полезные воронки

- Начало: `game_ready`, `run_start`, `wave_complete`, `run_complete`.
- Магазин: `offer_view`, `purchase_start`, `purchase_success`, `purchase_delivered`. На шагах фильтруйте один `offer_id`.
- Реклама: `rewarded_request`, `rewarded_open`, `rewarded_earned`. На шагах фильтруйте один `placement`.
- Сложность: `wave_start`, `wave_defeat` либо `wave_complete`. Сравнивайте одинаковые `run_id` и `wave`.

Документация: https://yandex.ru/dev/games/doc/ru/concepts/yandex-metrica и https://max-games.ru/plugin-yg/doc/metrica/.
